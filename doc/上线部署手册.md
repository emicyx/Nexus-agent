# Nexus 上线部署手册（私人部署版）

> 2026-08 实际部署验证过的完整流程：京东云 2C4G / Ubuntu 24.04 / Docker Compose / IP 直连（无域名免备案）。
> 代码已含上线加固（断连终止、Token 预算熔断、登录门、限流、健康检查、优雅停机等），见 roadmap「上线欠账清单修复」。

## 〇、前置准备清单

### 服务器
| 项 | 建议 | 说明 |
|---|---|---|
| 厂商/系统 | 京东云 / Ubuntu 24.04 LTS (UEFI) | 任意国内云均可 |
| 规格 | **2核 4GB** / 5Mbps / 50GB SSD | 内存是硬约束（Playwright Chromium 吃 0.5~1GB），2GB 会 OOM；2核够（重活在云端 LLM） |
| 带宽/流量 | 3~5Mbps，流量 ≥70GB 均够 | 1Mbps 首屏 2~3 秒，可忍但体验差 |

### 密钥材料（各不相同，`openssl rand -hex 32` 生成）

| 变量 | 用途 | 备注 |
|---|---|---|
| `QWEN_API_KEY` | 百炼 LLM/embedding | 自己的 key |
| `APP_API_KEY` | 后端 `/v1/*` 服务端鉴权 | 前端代理自动注入，浏览器不可见；**生产留空拒绝启动** |
| `APP_ACCESS_PASSWORD` | 访客登录密码（登录门） | 自己要记住的 |
| `SESSION_SECRET` | 会话 Cookie 签名加固 | **.env.example 里没有，手动加** |
| `POSTGRES_PASSWORD` / `APP_DB_PASSWORD` | DB superuser / 应用账号 | |
| `REDIS_PASSWORD` | Redis 密码 | hex 生成，避免 URL 特殊字符转义问题 |
| `LLM_TOKEN_DAILY_BUDGET` | 日预算熔断 | 如 2000000；0=不限 |

### 可选
- 域名 + **ICP 备案**（境内机房绑 80/443 必须；纯 IP 访问不需要）→ 走 HTTPS 方案 B。

## 一、控制台（买完先做三件事）

1. 重置实例 root 密码并重启生效。
2. 记下公网 IP。
3. 安全组入方向**先只放行 22/TCP**（SSH），Web 端口等部署完成后再开。

## 二、服务器初始化

```bash
ssh root@公网IP
apt update && apt upgrade -y

# 2GB swap 当 OOM 保险（4GB 也建议）
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

## 三、安装 Docker + 镜像加速

```bash
apt install -y docker.io docker-compose-v2
systemctl enable --now docker
docker compose version
```

Docker Hub 国内超时（`dial tcp ... i/o timeout`）时配加速：

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{"registry-mirrors": ["https://docker.m.daocloud.io", "https://docker.1ms.run", "https://docker.1panel.live"]}
EOF
systemctl restart docker
```

需要的基础镜像共 4 个：`redis:7-alpine`、`python:3.11-slim`、`node:20-alpine`、`pgvector/pgvector:pg16`。
加速全失效时兜底（前缀拉取再改回原名，四镜像同理）：

```bash
docker pull docker.m.daocloud.io/library/redis:7-alpine
docker tag docker.m.daocloud.io/library/redis:7-alpine redis:7-alpine
```

## 四、代码上服务器（不依赖 GitHub 的私人部署姿势）

Windows 本机 PowerShell：

```powershell
# 项目目录下
git bundle create "$env:TEMP\nexus.bundle" --all
scp "$env:TEMP\nexus.bundle" root@公网IP:/opt/
git remote add server ssh://公网IP/opt/nexus.git   # 一次性，以后直接推
```

服务器：

```bash
git clone /opt/nexus.bundle /opt/myAgent
git init --bare /opt/nexus.git
```

以后更新：本地 `git push server master` → 服务器 `cd /opt/myAgent && git pull /opt/nexus.git master && make rebuild`。

## 五、生产 `.env`

```bash
cd /opt/myAgent && cp .env.example .env && nano .env
```

必填项（密钥禁止使用示例文件里的占位串如 `change-me-...` / `my-redis-secret`，等于裸奔）：

```
QWEN_API_KEY=sk-...
APP_ENV=production
APP_API_KEY=<随机①>
APP_ACCESS_PASSWORD=<登录密码>
SESSION_SECRET=<随机③，手动新增此行>
POSTGRES_PASSWORD=<强口令>
APP_DB_PASSWORD=<强口令>
REDIS_PASSWORD=<随机hex>
REDIS_URL=redis://:<REDIS_PASSWORD同值>@redis:6379/0   # 主机名必须是 redis，不是 localhost！
LLM_TOKEN_DAILY_BUDGET=2000000
```

> ⚠️ 容器内 `localhost` 不是 Redis/PG——连接串主机名一律用 compose 服务名（`redis`/`postgres`）。

## 六、启动与验证

```bash
make up                        # = docker compose up --build -d，首次几分钟（拉镜像+装Chromium）
docker compose ps              # 等三容器 healthy（backend 有 30s 启动宽限）
curl http://127.0.0.1:8000/health
# 期望：{"status":"ok","checks":{"db":"ok","redis":"ok"}}
```

首次启动自动完成：PG 空 Volume 初始化（pgvector/zhparser 扩展 + 最小权限应用账号）→ 自动建表 → LLM 预热 → 沙箱清理调度。无需手动迁移。

**数据目录权限（bind mount 关键 · 2026-08-25 线上事故沉淀）**：`./backend/data` 不存在时由 Docker 以 **root** 自动创建，而容器以 `appuser(uid=1000)` 运行——不预授权则 `fetch_url` 等文件工具在 `mkdir /app/data/outputs` 时报 `[Errno 13] Permission denied`。镜像内的 chown 会被 bind mount 遮蔽，必须在**宿主机**授权：

```bash
# 首次部署：make up 之前执行一次
mkdir -p backend/data/outputs && chown -R 1000:1000 backend/data

# 已部署环境的在线修复（无需重启；bind mount 下同修宿主目录）
docker exec -u 0 $(docker ps -qf name=backend) chown -R 1000:1000 /app/data
```

排障：`docker compose logs backend --tail 50`（每条日志带 request-id 可串全链路）。

## 七、初始化业务数据

生产默认**不灌种子**（`SEED_DEMO_DATA=false`，数据卫生设计）。恢复内置 Agents/Tools/Skills/Schemas/Crews（幂等）：

```bash
docker compose exec backend python -c "import asyncio; from app.db.seed import ensure_seed; asyncio.run(ensure_seed())"
```

知识库文档**不在种子内**，用聊天页的文档上传功能重新灌真实语料（embedding 成本极低）。

## 八、开放访问（二选一）

**方案 A：IP 直连（免备案，本次采用）**
- 安全组放行 **TCP 3000**，访问 `http://公网IP:3000` → 跳 `/login` → 输 `APP_ACCESS_PASSWORD`。
- 注意：明文 HTTP，勿在公共 WiFi 使用。

**方案 B：域名 + HTTPS（需 ICP 备案）**
- `apt install caddy`，Caddyfile：`/health` → `127.0.0.1:8000`，其余 → `127.0.0.1:3000`；安全组放行 80/443；compose 3000 改绑 `127.0.0.1:3000:3000`。
- Nginx 的话必须 `proxy_buffering off`（SSE）+ `proxy_read_timeout 3600s`。

## 九、部署日收尾（运维三件套）

```bash
# 1. 数据库每日备份（crontab -e），保留 14 天
0 4 * * * cd /opt/myAgent && docker compose exec -T postgres pg_dump -U nexus nexus | gzip > /var/backups/nexus-$(date +\%F).sql.gz && find /var/backups -name "nexus-*.sql.gz" -mtime +14 -delete

# 2. 拨测：UptimeRobot 盯 http://IP:3000（方案B盯 https://域名/health，真探DB+Redis）

# 3. 巡检：make logs / docker compose ps / curl -H "X-API-Key: ..." http://127.0.0.1:8000/metrics
```

磁盘超 85%、Token 用量超 80% 均自动打告警日志；沙箱产物 7 天自动清理。

## 十一、日常运维

| 场景 | 操作 |
|---|---|
| 更新代码 | 本地 `git push server master` → 服务器 `git pull /opt/nexus.git master && make rebuild` |
| 回滚 | 服务器 `git checkout <旧提交> . && make rebuild`（数据在 pgdata 卷 + ./backend/data 不受影响） |
| 停机 | `docker compose down`（优雅：等在跑对话收尾 ≤60s） |
| 看日志 | `make logs` |
| 进数据库 | `make psql` |

## 十二、本次部署踩坑记录

1. **Docker Hub 超时** → 配 daemon.json 镜像加速（见三）。
2. **Redis ConnectionError** → `.env.example` 示例注释写 `localhost`，容器内必须用服务名 `redis`。
3. **占位密码** → 照抄示例串（`my-redis-secret` 等）等于没设，全部换 `openssl rand -hex 32`。
4. **线上无内置配置** → 预期行为（生产不灌种子），按七手动灌。
