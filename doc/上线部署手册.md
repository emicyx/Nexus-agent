# Nexus 上线部署手册（私人部署版）

> 2026-08 实际部署验证过的完整流程：京东云 2C4G / Ubuntu 24.04 / Docker Compose / IP 直连（无域名免备案）。
> 代码已含上线加固（断连终止、Token 预算熔断、登录门、限流、健康检查、优雅停机等），见 roadmap「上线欠账清单修复」。

## 〇、前置准备清单

### 服务器
| 项 | 建议 | 说明 |
|---|---|---|
| 厂商/系统 | 京东云 / Ubuntu 24.04 LTS (UEFI) | 任意国内云均可 |
| 规格 | **2核 4GB** / 5Mbps / 50GB SSD | 内存是硬约束（Playwright Chromium 吃 0.5~1GB），2GB 会 OOM；2核够（重活在云端 LLM） |
| 带宽/流量 | 3~5Mbps，流量 ≥70GB 均够 | 1Mbps 首屏 2~3 秒，可忍但体验差 |

### 密钥材料（各不相同，`openssl rand -hex 32` 生成）

| 变量 | 用途 | 备注 |
|---|---|---|
| `QWEN_API_KEY` | 百炼 LLM/embedding | 自己的 key |
| `APP_API_KEY` | 后端 `/v1/*` 服务端鉴权 | 前端代理自动注入，浏览器不可见；**生产留空拒绝启动** |
| `APP_ACCESS_PASSWORD` | 访客登录密码（登录门） | 自己要记住的 |
| `SESSION_SECRET` | 会话 Cookie 签名加固 | **.env.example 里没有，手动加** |
| `POSTGRES_PASSWORD` / `APP_DB_PASSWORD` | DB superuser / 应用账号 | |
| `REDIS_PASSWORD` | Redis 密码 | hex 生成，避免 URL 特殊字符转义问题 |
| `LLM_TOKEN_DAILY_BUDGET` | 日预算熔断 | 如 2000000；0=不限 |

### 可选
- 域名 + **ICP 备案**（境内机房绑 80/443 必须；纯 IP 访问不需要）→ 走 HTTPS 方案 B。

## 一、控制台（买完先做三件事）

1. 重置实例 root 密码并重启生效。
2. 记下公网 IP。
3. 安全组入方向**先只放行 22/TCP**（SSH），Web 端口等部署完成后再开。

## 二、服务器初始化

```bash
ssh root@公网IP
apt update && apt upgrade -y

# 2GB swap 当 OOM 保险（4GB 也建议）
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

## 三、安装 Docker + 镜像加速

```bash
apt install -y docker.io docker-compose-v2
systemctl enable --now docker
docker compose version
```

Docker Hub 国内超时（`dial tcp ... i/o timeout`）时配加速：

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{"registry-mirrors": ["https://docker.m.daocloud.io", "https://docker.1ms.run", "https://docker.1panel.live"]}
EOF
systemctl restart docker
```

需要的基础镜像共 4 个：`redis:7-alpine`、`python:3.11-slim`、`node:20-alpine`、`pgvector/pgvector:pg16`。
加速全失效时兜底（前缀拉取再改回原名，四镜像同理）：

```bash
docker pull docker.m.daocloud.io/library/redis:7-alpine
docker tag docker.m.daocloud.io/library/redis:7-alpine redis:7-alpine
```

## 四、代码上服务器（不依赖 GitHub 的私人部署姿势）

Windows 本机 PowerShell：

```powershell
# 项目目录下
git bundle create "$env:TEMP\nexus.bundle" --all
scp "$env:TEMP\nexus.bundle" root@公网IP:/opt/
git remote add server ssh://公网IP/opt/nexus.git   # 一次性，以后直接推
```

服务器：

```bash
git clone /opt/nexus.bundle /opt/myAgent
git init --bare /opt/nexus.git
```

以后更新：本地 `git push server master` → 服务器 `cd /opt/myAgent && git pull /opt/nexus.git master && make rebuild`。

## 五、生产 `.env`

```bash
cd /opt/myAgent && cp .env.example .env && nano .env
```

必填项（密钥禁止使用示例文件里的占位串如 `change-me-...` / `my-redis-secret`，等于裸奔）：

```
QWEN_API_KEY=sk-...
APP_ENV=production
APP_API_KEY=<随机①>
APP_ACCESS_PASSWORD=<登录密码>
SESSION_SECRET=<随机③，手动新增此行>
POSTGRES_PASSWORD=<强口令>
APP_DB_PASSWORD=<强口令>
REDIS_PASSWORD=<随机hex>
REDIS_URL=redis://:<REDIS_PASSWORD同值>@redis:6379/0   # 主机名必须是 redis，不是 localhost！
LLM_TOKEN_DAILY_BUDGET=2000000
```

> ⚠️ 容器内 `localhost` 不是 Redis/PG——连接串主机名一律用 compose 服务名（`redis`/`postgres`）。

## 六、启动与验证

```bash
make up                        # = docker compose up --build -d，首次几分钟（拉镜像+装Chromium）
docker compose ps              # 等三容器 healthy（backend 有 30s 启动宽限）
curl http://127.0.0.1:8000/health
# 期望：{"status":"ok","checks":{"db":"ok","redis":"ok"}}
```

首次启动自动完成：PG 空 Volume 初始化（pgvector/zhparser 扩展 + 最小权限应用账号）→ 自动建表 → LLM 预热 → 沙箱清理调度。无需手动迁移。

**数据目录权限（bind mount 关键 · 2026-08-25 线上事故沉淀）**：`./backend/data` 不存在时由 Docker 以 **root** 自动创建，而容器以 `appuser(uid=1000)` 运行——不预授权则 `fetch_url` 等文件工具在 `mkdir /app/data/outputs` 时报 `[Errno 13] Permission denied`。镜像内的 chown 会被 bind mount 遮蔽，必须在**宿主机**授权：

```bash
# 首次部署：make up 之前执行一次
mkdir -p backend/data/outputs && chown -R 1000:1000 backend/data

# 已部署环境的在线修复（无需重启；bind mount 下同修宿主目录）
docker exec -u 0 $(docker ps -qf name=backend) chown -R 1000:1000 /app/data
```

排障：`docker compose logs backend --tail 50`（每条日志带 request-id 可串全链路）。

## 七、初始化业务数据

生产默认**不灌种子**（`SEED_DEMO_DATA=false`，数据卫生设计）。恢复内置 Agents/Tools/Skills/Schemas/Crews（幂等）：

```bash
docker compose exec backend python -c "import asyncio; from app.db.seed import ensure_seed; asyncio.run(ensure_seed())"
```

知识库文档**不在种子内**，用聊天页的文档上传功能重新灌真实语料（embedding 成本极低）。

## 八、开放访问（二选一）

**方案 A：IP 直连（免备案，本次采用）**
- 安全组放行 **TCP 3000**，访问 `http://公网IP:3000` → 跳 `/login` → 输 `APP_ACCESS_PASSWORD`。
- 注意：明文 HTTP，勿在公共 WiFi 使用。

**方案 B：域名 + HTTPS（需 ICP 备案）**
- `apt install caddy`，Caddyfile：`/health` → `127.0.0.1:8000`，其余 → `127.0.0.1:3000`；安全组放行 80/443；compose 3000 改绑 `127.0.0.1:3000:3000`。
- Nginx 的话必须 `proxy_buffering off`（SSE）+ `proxy_read_timeout 3600s`。

## 十四、S1 QQ 渠道部署（NapCat / OneBot 反向 WS，2026-09-15）

> 开发期部署在**本机 compose 栈**（napcat 为第 5 容器）；云端迁移是收官步骤（执行计划 §10）。

### 1. env 配置（`.env`）

| 变量 | 说明 |
|---|---|
| `ONEBOT_WS_TOKEN` | WS 鉴权 token。生成：`python -c "import secrets;print(secrets.token_urlsafe(32))"`。未配置时 backend 拒绝一切 WS 连接（QQ 通道关闭），Web 端不受影响 |
| `QQ_OWNER_IDS` | 逗号分隔 QQ 号（你自己的 QQ，即 owner 白名单）。名单外消息记 WARNING 并静默 |

### 2. 部署步骤

```bash
#    URL:   ws://backend:8000/v1/channels/onebot/ws?token=<ONEBOT_WS_TOKEN 同值>
```

### 5. 注意事项

- **单实例铁律**：同一 QQ 号只能跑一个 NapCat。本机已有独立 NapCat 安装的先停用；云端迁移时"先起云端、验收连通后再停本机"（互踢窗口最小化）。

- 移动端 QQ 不受影响（NapCat 占用 PC 协议位）。

## 十五、S2 定时任务与推送部署（调度器 + 巡检告警 + KB 日报，2026-09-16）

### 1. 变更范围

- **alembic 0010**（`backend/alembic/versions/0010_jobs.py`）：新增 `jobs` / `job_runs` 两表（纯新增，可前滚不可破坏）。开发库走 create_all 自动建表；云端干净库走 `alembic upgrade head`。
- **新依赖**：`apscheduler~=3.11`（烧进镜像，安全不变量 7；锁 3.x——4.x 是 API 不兼容重写版）。
- **seed**：新增 `ops_patrol` / `daily_digest` 两个 crew + 三个默认 job（ops_patrol 每 30 分钟 state_change 巡检 / ops_daily_report 每日 8:00 日报 / kb_daily_digest 每日 21:00 KB 日报）。**注意坑**：`SEED_DEMO_DATA=false` 时启动跳过 seed，需容器内手动 `ensure_seed()` 一次。

### 2. env 清单（全部进 `.env.example`）

```bash
# 主动推送目标（egress 唯一目标来源，安全不变量 1；建议私聊直达）
QQ_ALERT_TARGET={"type":"private","user_id":<owner QQ>}
# 巡检目标（2-5 个真实 URL，至少一个公网站点做对照；http_check 只查这里，模型不可指定 URL）
MONITOR_TARGETS=[{"name":"backend","url":"http://backend:8000/health","expect_status":200,"timeout_s":10},
                 {"name":"frontend","url":"http://frontend:3000/chat","expect_status":200,"timeout_s":10},
                 {"name":"baidu","url":"https://www.baidu.com","expect_status":200,"timeout_s":10}]
# cron 时区（安全不变量 9：显式时区，缺省 Asia/Shanghai）
JOB_TIMEZONE=Asia/Shanghai
# eval 全局开关（§5.6 零外发第二道闸）：true = 一切 job 推送强制抑制
NEXUS_EVAL_MODE=false
# 调度总开关（回滚用）：false = 不注册任何定时任务
JOBS_ENABLED=true
```

注意：frontend 目标用 `/chat`（Next.js 根路径 `/` 是 307 重定向且无 Location 头，跟不动，会误报 DOWN——2026-09-16 实测）。私网/内网目标由运维在 MONITOR_TARGETS 显式声明（http_check 直连，不走 fetch_url/net_guard 路径，也不为巡检放松 net_guard）。

### 3. 部署步骤

```bash
docker compose build backend frontend   # apscheduler 必须随镜像重建
docker compose up -d
# SEED_DEMO_DATA=false 的环境补一次种子：
docker exec myagent-backend-1 python -c "import asyncio; from app.db.seed import ensure_seed; asyncio.run(ensure_seed())"
# 验证：
curl -s localhost:8000/health                                  # {"status":"ok"}
curl -s localhost:8000/v1/jobs | python -m json.tool           # 三个默认 job + next_run_at
docker logs myagent-backend-1 2>&1 | grep job_scheduler        # "started（注册 3 个任务，时区 Asia/Shanghai）"
```

### 4. 验收清单

- [ ] eval 零外发演练：`python -m testing.eval.job_adapter --job ops_daily_report --base-url http://localhost:8000` → `pushed_to == 'suppressed(eval)'`，QQ 无任何消息到达
- [ ] 真实推送：`curl -X POST localhost:8000/v1/jobs/2/run -H 'Content-Type: application/json' -d '{"eval":false}'` → owner QQ 收到巡检日报（pushed_to=qq）
- [ ] 巡检基线与告警：首轮 ops_patrol 建基线不推送；人为停一个监控目标，下一巡检周期（30 分钟内）收到 down 告警，恢复后收到 up 通知
- [ ] 断连演练：`docker compose stop napcat` 一段时间 → 期间 job_runs 如实记 `failed(channel_offline)`（该推的 run）→ 恢复后自动重连续推，无静默丢失；`/metrics` onebot_connected 可见变化
- [ ] 早 8:00 巡检日报 + 21:00 KB 日报连续 7 天到达 QQ（本机不睡眠前提，账本如实记录）
- [ ] 前端 /config → Jobs 页签：列表 / 启停 / 运行(eval) / 最近运行状态可见

### 5. 回滚

```bash
# 方式一（推荐）：调度总开关，job 不再触发（数据与通道保留）
#   .env 设 JOBS_ENABLED=false 后 docker compose restart backend
# 方式二：Web 端 /config → Jobs 逐个停用（PATCH enabled=false）
# 方式三：通道层回滚 docker compose stop napcat（job_runs 将如实记 channel_offline）
# 表结构只新增不删除，无需回滚迁移
```

### 6. 注意事项

- **每 job 并发 = 1**：调度与手动触发共享锁；运行中再触发，手动路径返回 409，调度路径跳过本轮。
- **熔断**：连续失败达 `max_consecutive_failures`（默认 5）自动停用 + 推一条告警后静默；eval run 不计数不触发。
- **eval 抑制是双闸**：单次 run 的 `eval:true` 或全局 `NEXUS_EVAL_MODE=1` 任一命中，egress 一律不发送并记 `suppressed(eval)`（先于目标解析与渠道检查）。
- **token 成本口径**：job_runs.tokens_used 是 token_budget 会话差值（按运行会话归集的近似值），cost_note 有注明。
- **改 .env 后必须 `docker compose up -d` 重建容器**：`docker compose restart` 不重读 env_file（env 在容器创建时注入）——2026-09-16 实测：改了 MONITOR_TARGETS 后 restart，容器内仍是旧值，巡检持续误报 DOWN。
- **NAPCAT_QUICK_PASSWORD**：napcat 容器只有 ACCOUNT 时快速登录仍回退二维码；硬杀容器（Docker Desktop 崩溃/强杀）会打掉 NTQQ 登录态需重扫码（2026-09-16 实测）。要免扫码可再配 `NAPCAT_QUICK_PASSWORD`（QQ 密码，风险自担）。

## 十六、S3' 钉钉告警备用通道部署（QQ 推送失败兜底，2026-09-17）

> 背景与边界：钉钉"监听公司群公告"不可行（非企业管理员进不了群、公告不 @ 机器人收不到、无个人消息 API），本通道定位仅为 **QQ 告警的备用出口**（2026-09-16 NapCat 风控失联约 5 小时的教训）。不需要企业内部应用、不需要 dingtalk-stream SDK、零新依赖（requests 已在镜像）。

### 1. 钉钉侧一次性配置（手机/桌面端均可）

1. 手机钉钉建一个群（成员只有自己，任意群名，如"Nexus 告警"）。
2. 群设置 → 机器人 → 添加机器人 → **自定义**（通过 Webhook 接入）。
3. 安全设置选 **加签** → 完成，记下两样东西：**Webhook 完整 URL**（含 access_token 参数）与**加签密钥**（SEC 开头）。

### 2. env 变量（加到 .env 后必须 `docker compose up -d` 重建，restart 不重读 env_file）

```bash
DINGTALK_PUSH_WEBHOOK=https://oapi.dingtalk.com/robot/send?access_token=xxxx   # 空 = 备推关闭
DINGTALK_PUSH_SECRET=SECxxxxxxxxxxxxxxxx                                        # 与 webhook 成对
DINGTALK_PUSH_MODE=backup    # backup=仅 QQ 推送 failed(...) 时兜底（缺省）/ always=每次双发 / off
```

### 3. 部署步骤


### 6. 注意事项

- **本机时钟偏差 >1 小时会拒签**（errcode 310000 "sign not match"）：webhook 加签的 timestamp 必须接近钉钉服务器时间。
- **限流 20 条/分钟**（机器人硬限）：state_change + 日报天然稀疏，正常用不到；连续触发演练时留意。
- 落账语义：`job_runs.pushed_to` 永远记主通道（QQ）结果，备推结果在 `pushed_to_backup`（'dingtalk' / 'failed(...)' / null）；agent 侧 push_message 工具回话会如实说明"主失败已兜底"。
- `DINGTALK_PUSH_MODE=always` 是双发（每次 QQ+钉钉都收），仅调试期用；日常保持 backup。
