# SOP 04 · 图标与精灵图（PNG / 精灵表 / Aseprite）

> 目标：为英雄、技能、物品、UI 提供图片资源：静态图、打包精灵表、逐帧动画。
> 前置：SOP 01；配合 SOP 02。
> 源文档：[assets-and-sprite-sheets](../TeamfightManager2Mod/docs/assets-and-sprite-sheets.md)

---

## 1. 核心概念：一个「资产」是一组文件

游戏不总是直接使用一个图片文件。精灵/图标/动画往往是**共享同一路径的一组子资产**：

```text
mods/example/champions/fire_mage.aseprite   →  asset/example/champions/fire_mage
游戏准备该资产时可能派生：
  asset/example/champions/fire_mage#sheet    ← 图集（会真正被绘制的图）
  asset/example/champions/fire_mage#anim     ← 命名动画（帧矩形 + 时长）
  asset/example/champions/fire_mage#data     ← 命名静图矩形
  asset/example/champions/fire_mage#lanim    ← 分层动画数据（少数场景）
```

`#` 后面的部分**不是文件扩展名**，是同一资产的命名成员。大多数 mod 只需要
`#sheet`、`#anim`、`#data`。

### 标签（tag）的含义

精灵表 = 一张大图装很多小图；标签 = 从中选取某个小图/某段动画的名字。

- 技能图标表的标签：`fire_skill`、`fire_skill2`、`fire_ult`（存于 `#data`）。
- 英雄动画的标签：`idle`、`run`、`attack`、`skill`、`skill2`、`ult`、`dead`（存于 `#anim`）。
- 动作里写 `action_name: "skill"`，游戏就去找该英雄 `#anim` 里名为 `skill` 的动画。

## 2. 制作路线选择

| 你要的东西 | 路线 | 章节 |
|---|---|---|
| 单张技能图标 / 简单图片 | 直接放 PNG，引用路径（无扩展名） | §3 |
| 一张图集装多个图标 | 手动精灵表（PNG + `.sprite_sheet`）或 Aseprite `Sheet`/`PackedSheet` | §4 |
| 英雄动画（正式） | Aseprite `Animation`，或手动 PNG + `.fanim` | §5 |
| 英雄动画（测试期占位） | 静态 PNG | §3 |

## 3. 静态 PNG（最简单）

把 PNG 放进 mod 任意位置，按去扩展名路径引用：

```text
mods/example/icons/fire_skill.png  →  asset/example/icons/fire_skill
```

作为英雄 `sprite` 时（测试占位）：

```json
{ "sprite": "asset/example/champions/fire_mage_idle" }
```

- **不要设 `anim_prefix`**。整图作为单帧精灵，游戏自动生成
  `idle/attack/skill/skill2/ult/dead/run` 的简单兜底动画。
- 适合验证英雄能否加载；成品动画英雄请用 §5。

## 4. 精灵表（静图集）

### 方式 A：Aseprite

在 **Aseprite 精灵属性的用户数据**（sprite user data）文本框里写 JSON：

```json
{ "sheet_type": "Sheet" }
```

或裁掉透明边距的紧凑版：

```json
{ "sheet_type": "PackedSheet" }
```

产物：`#sheet` + `#data`。标签名由**图层名 + 帧号**生成：
图层 `fire_skill` 的第 0 帧 → 标签 `fire_skill_0`。

### 方式 B：手动 PNG + JSON

命名模式（`#` 是文件名的一部分）：

```text
mods/example/icons/spells#sheet.png          ← 图集图片
mods/example/icons/spells#data.sprite_sheet  ← 矩形数据
```

`.sprite_sheet` 里是**归一化 UV 矩形**（`0.0`–`1.0`，左上角为原点）：

```json
{
  "images": {
    "fire_skill":  { "x": 0.0,  "y": 0.0, "w": 0.25, "h": 0.5 },
    "fire_skill2": { "x": 0.25, "y": 0.0, "w": 0.25, "h": 0.5 },
    "fire_ult":    { "x": 0.5,  "y": 0.0, "w": 0.25, "h": 0.5 }
  }
}
```

然后数据英雄用（SOP 02 §7）：

```json
"skill_icon": { "source": "asset/example/icons/spells", "tags": ["fire_skill", "fire_skill2", "fire_ult"] }
```

适用：技能图标、物品图标、UI 图标、内联文本图标。

## 5. 动画

### 方式 A：Aseprite（推荐）

精灵用户数据 JSON：

```json
{
  "sheet_type": "Animation",
  "layers": ["body", "weapon"],
  "anchor_x": 0.5,
  "anchor_y": 0.5
}
```

| `sheet_type` | 用途 | 提供的子资产 |
|---|---|---|
| `Animation` | 英雄精灵、动画特效 | `#sheet`、`#anim` |
| `Sheet` | 保持画布尺寸的静图表 | `#sheet`、`#data` |
| `PackedSheet` | 裁边的静图表 | `#sheet`、`#data` |
| `LayeredAnimation` | 分层动画（对齐基础游戏的分层设置时才用） | `#sheet`、`#data`、`#anim`、`#lanim` |

规则：

- **Aseprite 时间线上的 tag 就是 `#anim` 里的动画名**：时间线有 `attack` tag，
  `action_name: "attack"` 就能播放它。帧时长同样来自 Aseprite 时间线。
- `layers`：参与合成帧的图层名，必须与 Aseprite 实际图层名**完全一致**。
- `anchor_x/anchor_y`：原图画布内的归一化锚点（默认 0.5, 0.5 中心），
  用于帧被裁边后保持视觉锚定。
- 没有 `sheet_type` 的 `.aseprite` 文件只作为源文件加载，不会提供渲染子资产。

### 方式 B：手动 PNG + `.fanim`

```text
mods/example/champions/fire_mage#sheet.png    ← 图集
mods/example/champions/fire_mage#anim.fanim   ← 动画数据
```

⚠️ `.fanim` 的矩形是**像素坐标**（与 `.sprite_sheet` 的归一化 UV 不同）：

```json
{
  "anims": {
    "idle": {
      "frames": [
        { "duration": 0.12, "data": { "x": 0,  "y": 0, "w": 64, "h": 64 } },
        { "duration": 0.12, "data": { "x": 64, "y": 0, "w": 64, "h": 64 } }
      ]
    },
    "attack": { "frames": [ /* ... */ ] }
  }
}
```

英雄引用（tags 原样复制）：

```json
{ "sprite": "asset/example/champions/fire_mage", "anim_prefix": "" }
```

## 6. 复用一份动画源给多个变体（anim_prefix）

一个 Aseprite 文件含多个角色/变体时，给 tag 加前缀：

```text
eagle_idle / eagle_run / eagle_attack / eagle_skill
```

数据英雄侧剥掉前缀：

```json
{ "sprite": "asset/base/aseprite_resources/champions/druid", "anim_prefix": "eagle_" }
```

英雄得到的标签即 `idle / run / attack / skill`。**不带前缀的 tag 也会保留**，
因此同一源文件可以放所有变体共用的通用标签。

`anim_prefix` 取值规则：

| 场景 | `anim_prefix` |
|---|---|
| 静态 PNG | 不设 |
| 标签已是标准名（`idle` 等） | `""`（原样复制） |
| 源文件带变体前缀 | 具体前缀，如 `"eagle_"` |

## 7. 动作 ↔ 动画标签的对应

`action_name` 同时是玩法动作名和视觉查找键。动作开始时，渲染器尝试播放同名动画 tag：
Aseprite 里 = 时间线 tag 同名；`.fanim` 里 = `anims.<tag>` 存在。
`action_name` 用了非标准名（如 `fire_cast`），标签也得叫 `fire_cast`。
缺标签通常表现为英雄能加载但该动作没有预期动画。

## 8. 操作步骤汇总（给数据英雄配齐视觉）

1. （测试期）`sprite` 指向任意 PNG 或基础精灵 → 进游戏验证加载。
2. 制作技能图标：三张 PNG（`skill_icons`）或一张表（`skill_icon` + tags）。
3. 制作英雄动画：Aseprite 设 `sheet_type: "Animation"`、命名
   `idle/run/attack/skill/skill2/ult/dead` tags、写 `layers`。
4. `.data_champion` 里绑定 `sprite` + `anim_prefix`。
5. （可选）`view_projectiles` / `view_effects` 为弹道和特效配视觉
   （name 与效果内 name 精确匹配，见
   [Visual Bindings](../TeamfightManager2Mod/docs/data-champion-schema/visual-bindings.md)）。
6. 重启验证。

## 9. 排错速查（详见 [SOP 10](10-测试与故障排查.md)）

| 症状 | 排查 |
|---|---|
| 图片不加载 | 路径带了扩展名；文件不在 mod 内；大小写/拼写不符；sheet tag 引用的 `#sheet`/`#data` 缺一 |
| 手写表显示错图 | `.sprite_sheet` 必须归一化值（0.0–1.0）；`.fanim` 必须像素值；JSON tag 与表内 tag 拼写不一致 |
| Aseprite 不动 | 缺 `"sheet_type": "Animation"`（或 `LayeredAnimation`）；时间线 tag 与动作名不匹配；`layers` 名与实际图层名不一致；动画源缺 `anim_prefix`；带前缀源的前缀拼写不对 |
| `Sheet`/`PackedSheet` 标签取不到 | 标签名是 `<图层名>_<帧号>`（如 `fire_skill_0`） |
