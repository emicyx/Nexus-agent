# SOP 03 · 文本与 i18n（本地化）

> 目标：为英雄/物品/UI 提供名字与描述文本，支持多语言，并让游戏文本系统找到它们。
> 前置：SOP 01；通常配合 SOP 02。
> 源文档：[asset-overrides-and-i18n](../TeamfightManager2Mod/docs/asset-overrides-and-i18n.md)

---

## 1. i18n 文件格式

i18n 文件是**按语言分组**的 JSON，放在 mod 内（惯例 `text/` 目录）：

```text
mods/my_mod/text/champion.i18n     →  asset/my_mod/text/champion
```

```json
{
  "en": {
    "description": {
      "my_mod_fire_mage": {
        "name": "Fire Mage",
        "skill": "Launches a fire bolt.",
        "skill2": "Focuses flame energy.",
        "ult": "Burns all nearby enemies."
      }
    }
  },
  "ko": {
    "description": {
      "my_mod_fire_mage": {
        "name": "파이어 메이지",
        "skill": "화염 화살을 발사합니다.",
        "skill2": "화염 에너지를 집중합니다.",
        "ult": "주변의 모든 적을 태웁니다."
      }
    }
  }
}
```

- 每个语言一个顶层键（`en`、`ko`、……）。
- 键路径自由组织，但必须与引用处的查询路径一致（见第 2 节）。

## 2. 引用格式

数据文件里用 `#` 前缀 + `?` 查询路径引用 i18n：

```text
#asset/base/text/champion?description.my_mod_fire_mage.skill
 └────── 资产路径（无扩展名）──────┘└──────── JSON 键路径 ────────┘
```

即：读取 `asset/base/text/champion` 对应的 i18n 文件，取
`description.my_mod_fire_mage.skill` 处的字符串。

## 3. 关键机制：合并进基础文本表（新英雄必须做）

英雄 UI（列表、ban/pick、tooltip、技能描述）大多从**基础冠军文本表**
`asset/base/text/champion` 读取，所以新英雄的键要**合并**进去。
在 mod 根目录创建 `mod.override_info`：

```json
{
  "asset/base/text/champion": {
    "remapping": "asset/my_mod/text/champion",
    "type": "merge"
  }
}
```

这样 `#asset/base/text/champion?description.my_mod_fire_mage.skill` 就能命中你文件里的键。

> `merge` / `override` 的完整语义、与其他资产的组合见
> [SOP 06 · 资产覆盖与合并](06-资产覆盖与合并.md)。
> 文本和 JSON 小改动**一律用 `merge`**，只有整体替换才用 `override`。

## 4. 场景对照

| 场景 | 做法 |
|---|---|
| 新英雄的名字/描述 | i18n 文件 + `mod.override_info` merge 到 `asset/base/text/champion`（本文第 3 节） |
| 改版英雄的**技能描述** | 指向你自己的命名空间：`#asset/my_mod/text/champion?rework_fighter.skill`，**不需要** merge（引用的是自己的资产路径） |
| 改版英雄的**名字**或其他以英雄 id 为键的基础文本 | 需要 merge 到 `asset/base/text/champion` 覆盖原键（否则游戏里仍显示旧名） |
| 追加 UI 文本 | merge 到 `asset/base/text/ui` 等对应表 |
| 原生 mod 的文本 | 同样走 i18n；`name()`/`description()` 返回 i18n 键；服务器新闻也接受 i18n 键 |

## 5. 富文本标记

描述可使用与基础游戏相同的内联标记：

```text
Deals <#ff9028ff>60<> + <i#asset/base/ui/banpick/champion_stat_icon:ad_0><#ff9028ff>80% AD<> physical damage.
```

| 标记 | 作用 |
|---|---|
| `<#rrggbbaa>text<>` | 给文本上色 |
| `<i资产路径:标签>` | 从精灵表插入内联图标；路径是**共享表路径**（不带 `#sheet`），矩形取自 `路径#data`，图取自 `路径#sheet` |

**不确定怎么写时，去 `base_unpacked`（SOP 00 解包）看基础文本文件，抄现有英雄/物品描述的写法。**

## 6. 操作步骤汇总（新英雄完整流程）

1. 创建 `mods/my_mod/text/champion.i18n`，写入各语言的 `description.<champion_id>.*` 键。
2. 创建/编辑 `mods/my_mod/mod.override_info`，加 merge 规则（第 3 节）。
3. `.data_champion` 的 `description` 字段写
   `#asset/base/text/champion?description.<champion_id>.skill` 形式的键。
4. 重启游戏验证：英雄列表显示名字、技能 tooltip 显示描述文本。

## 7. 验证与排错

| 症状 | 排查（详见 [SOP 10](10-测试与故障排查.md)） |
|---|---|
| 文本缺失/空白 | i18n 文件不是合法 JSON；merge 规则漏写或 `type` 不是 `merge`；目标路径写错（应为 `asset/base/text/champion`）；查询路径与 JSON 实际键路径不一致 |
| 显示的是键名本身 | 键路径拼写/层级与文件不匹配 |
| 改版后名字没变 | 名字在基础文本表里，必须 merge 覆盖；只改 gameplay 数据不会动文本 |
| mod 被禁用 | `mod.override_info` JSON 非法（诊断弹窗会指出） |

## 8. 兼容性提示

- 多个 mod 修改同一个键时，最终结果受启用顺序影响——尽量只加新键，少改公共键。
- 给公共 UI 文本加键用 merge；不要为了小改去整体 override 大型文本/布局文件。
