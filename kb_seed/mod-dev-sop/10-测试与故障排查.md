# SOP 10 · 测试与故障排查

> 目标：建立标准的「改动 → 验证」循环，并按症状快速定位问题。
> 适用：所有 mod 类型，贯穿全程。
> 源文档：[troubleshooting](../TeamfightManager2Mod/docs/troubleshooting.md) ·
> [getting-started §4-5](../TeamfightManager2Mod/docs/getting-started.md)

---

## 1. 标准测试循环

1. 修改文件（JSON / 图片 / DLL 等）。
2. **重启游戏**——这是最可靠的测试方式：mod 元数据、原生 DLL、大量启动资产
   都在游戏启动时加载，热加载不可靠。
3. 标题画面 → Mods 菜单确认启用状态。
4. **先看诊断弹窗**，再看内容是否生效。
5. 进对应场景验证（英雄池、ban/pick、对局、UI……）。

> 原生 mod 的循环 = 改码 → `cargo build --release` → 替换 DLL → 重启（SOP 08 §10）。

## 2. 第一入口：诊断弹窗

mod 加载失败时，游戏在**标题画面**弹出诊断信息，通常直接点名出问题的文件或 DLL
（非法 JSON、缺依赖、覆盖损坏、原生 DLL 问题等）。
**任何「没生效」都先看它。** 原生问题再看日志：
`%APPDATA%\TeamSamoyed\TeamfightManager2\data\log.log`（panic 记录在此）。

## 3. 症状 → 排查清单

### 3.1 Mod 不出现在列表

- [ ] 文件夹在 `mods/` 下
- [ ] 内含 `mod.mod_info`
- [ ] `mod.mod_info` 是合法 JSON
- [ ] `version` 形如 `0.1.0`
- [ ] 添加文件夹后重启过游戏

### 3.2 出现但无法启用（依赖问题）

- [ ] 依赖 mod 已安装
- [ ] 依赖版本满足要求
- [ ] `base` 要求与**当前游戏版本**（标题画面右下角）匹配——`base` 指游戏版本，不是基础资源
- [ ] 依赖已装但仍失败 → 看诊断弹窗（版本不匹配或依赖 mod 自身加载失败）

### 3.3 游戏禁用了 mod

- [ ] `mod.mod_info` / `mod.override_info` JSON 非法
- [ ] 原生 DLL 加载失败
- [ ] DLL 注册 id 与文件夹名不一致
- 修复后重启。

### 3.4 文本缺失/空白

- [ ] i18n 文件是合法 JSON
- [ ] merge 规则 `"type": "merge"` 且目标路径正确（如 `asset/base/text/champion`）
- [ ] 查询路径与 JSON 实际键路径一致：
  `#asset/base/text/champion?description.my_mod_fire_mage.skill`

### 3.5 图片不加载

- [ ] 资产路径**不含扩展名**
- [ ] 文件确在 mod 文件夹内
- [ ] 拼写与大小写完全匹配
- [ ] 技能图标指向合法 PNG 资产或精灵表 tag
- [ ] 用了表 tag：`source#sheet` 与 `source#data` 都存在
- [ ] 手写 `.sprite_sheet`：矩形是 0.0–1.0 归一化值（不是像素）

### 3.6 Aseprite 精灵不动

- [ ] 精灵用户数据有 `"sheet_type": "Animation"` 或 `"LayeredAnimation"`
- [ ] 时间线 tag 与英雄动作名匹配（`idle/attack/skill/skill2/ult`）
- [ ] 用户数据 `layers` 与实际图层名一致
- [ ] 动画源的英雄配了 `anim_prefix`（原样复制用 `""`）
- [ ] 用前缀源时 tag 真的带该前缀（`eagle_idle` ↔ `"anim_prefix": "eagle_"`）

### 3.7 精灵表 tag 显示错图

- [ ] JSON 里的 tag 与表数据中的 tag 拼写一致
- [ ] 手写 `.sprite_sheet` 用归一化值；`.fanim` 用像素值
- [ ] Aseprite `Sheet`/`PackedSheet` 的 tag 名是 `<图层名>_<帧号>`（`fire_skill_0`）

### 3.8 数据英雄不工作

- [ ] 扩展名 `.data_champion`
- [ ] 有 `attack`、`skill`、`skill2`（`ult` 可选）
- [ ] 枚举精确拼写（`Targeting`、`Enemy`、`BaseAttack`……区分大小写）
- [ ] 新英雄 id 唯一；改版 id 与基础英雄**完全一致**
- [ ] 描述键指向已合并进 i18n 的文本
- [ ] `sprite` 指动画源时 `anim_prefix` 存在；指 PNG 时不需要

### 3.9 改版不生效

- [ ] `.data_champion` / `ModChampionInfo::id()` 用的是精确基础英雄 id
- [ ] JSON 改版：扩展名正确、mod 无诊断错误
- [ ] 原生改版：DLL 用当前 SDK、以 `replace_champion` 注册（stable 为 `add_champion` 同 id）
- [ ] 改数据/重编 DLL 后重启过游戏
- [ ] 多人：每个玩家启用相同 mod、DLL 为兼容 SDK 构建
- [ ] 同 id 同时有 JSON 与原生注册 → 原生优先（可能不是你以为的那个在生效）
- [ ] 名字/描述旧文本：需 i18n merge 进 `asset/base/text/champion`（SOP 05 §2.4）

### 3.10 原生 DLL 不加载

- [ ] DLL 在 mod 文件夹内
- [ ] 导出了 `tfm2_mod_entry`（用了 `declare_mod!` / `declare_stable_mod!`）
- [ ] 注册 id 与 mod 文件夹同名
- [ ] 用匹配的 SDK 构建（classic：还要匹配游戏版本、Win x86_64 MSVC、release 构建 + release 游戏）
- [ ] 诊断提到 API 版本符号/版本不匹配 → 用当前 SDK 重编（classic）

### 3.11 原生 AI 钩子不运行

- [ ] DLL 无诊断错误加载
- [ ] 钩子在 `ModRegistration` 用 `add_draft_score_hook` / `add_player_input_ai` 注册
- [ ] mod 已启用且替换 DLL 后重启过
- [ ] `matches()` 对目标玩家返回 `true`
- [ ] `priority()` 没有被更高优先级钩子覆盖
- [ ] 返回的 `Input` 当前帧合法（非法替换输入被忽略）
- [ ] 观测场景确实用 `GameRunner` 模拟（对局或标题画面的模拟对局）
- 玩家输入 AI 调试起步：先一直 `Pass`，触发条件满足后再用
  `get_run_away_input()` / `get_recall_input()` / `is_safe_to_recall()` 等辅助构造输入。

### 3.12 读游戏数据编译不过（classic）

- [ ] 用当前 SDK（旧 SDK 可能没有新 `ClientData` 辅助）
- [ ] 代码在 `ModExtension` 内并先匹配 `Scene::InGame { data }`
- [ ] id 存在于当前存档（客户端没有该数据时查询返回 `None`）
- [ ] `Ref<'_, T>` 先于需要可变借用的调用（如存档写入）离开作用域
- [ ] 注解需要的类型名从 `mod_api::*` 导入（`Athlete`、`Team`、`MatchInfo`、`League`、
  `Tournament`、`ChampionInfo` 等已重导出）

### 3.13 存档数据不持久

- [ ] DLL 无诊断错误
- [ ] 在 InGame 场景访问
- [ ] `mod_id` 与文件夹名、注册 id 一致
- [ ] 写接口返回 `true`
- [ ] key/mod id 非空、<128 字节、无 NUL；值 ≤ 1 MiB
- [ ] 多人联盟存档：写方是主机
- [ ] 没在每帧清命名空间或覆写同值
- 记住：写入后走正常存档流程、读**同一存档位**验证。

### 3.14 原生服务依赖不工作

- [ ] 提供方列在消费方 `mod.mod_info` 依赖里
- [ ] 提供方已安装且其 DLL 无诊断错误
- [ ] 提供方在入口函数里 `GameCtx::register_service`
- [ ] 消费方用的提供方 mod id、服务 id、版本要求正确
- [ ] 两侧 `#[repr(C)]` 服务 vtable 布局一致
- 消费方有兜底路径时可能仍能加载但行为不同（如加成停留在兜底值）。

### 3.15 Workshop 上传失败

- [ ] Steam 在运行
- [ ] 上传器从游戏文件夹运行（与 Steam DLL 同目录）
- [ ] 拥有该游戏 app 权限
- [ ] Steam 要求时已接受 Workshop 法律协议
- [ ] `mod.mod_info` 可解析
- [ ] `preview.png/jpg`、`thumbnail.png/jpg`（如有）是合法图片
- [ ] 更新已有物品：`mod.workshop_id` 指向正确物品
- [ ] 原生 mod 用构建选项前 SDK 已装
- 已有编译 DLL 只想上传 → 取消勾选 **Build native Rust code before uploading**

### 3.16 上传器内原生构建失败

- [ ] 匹配的 SDK 在 `TFM2ModUploader.exe` 旁边
- [ ] `mod-sdk/deps` 有预构建 `mod-api` 文件
- [ ] `cargo`、`rustc` 可运行
- [ ] mod 有 `Cargo.toml` 或 `src/lib.rs` 之一
- [ ] 外部 crate 可下载或已在 Cargo 缓存
- [ ] mod 位于另一 Cargo workspace 内 → 给它的 `Cargo.toml` 加空 `[workspace]` 表或移出
- [ ] 公共 SDK 构建路径下**不要**把 `mod-api` 加进 `[dependencies]`（上传器自动注入）
- [ ] SDK 版本与目标游戏版本匹配

## 4. 测试的分层建议

| 层 | 验什么 |
|---|---|
| 骨架层 | Mods 菜单可见、可启用、无诊断（SOP 01） |
| 数据层 | 英雄/物品出现在游戏内、数值正确（SOP 02） |
| 表现层 | 文本、图标、动画、立绘正确（SOP 03 / 04 / 07） |
| 逻辑层 | 原生行为、钩子触发、UI 交互（SOP 08） |
| 持久层 | 存档写入/读回、多人主机写入（SOP 09） |
| 兼容层 | 禁用 mod 后还原；与其他 mod 共存；改版与存档交互（SOP 05） |
| 发布层 | 上传、更新、订阅者视角（SOP 11） |
