# SOP 06 · 资产覆盖与合并（mod.override_info）

> 目标：替换或合并**基础游戏的资产**——文本、精灵、UI 布局、JSON 数据等。
> 前置：SOP 01。
> 源文档：[asset-overrides-and-i18n](../TeamfightManager2Mod/docs/asset-overrides-and-i18n.md)

---

## 1. 何时用本 SOP（与相邻机制的区别）

| 想做的事 | 用哪个机制 |
|---|---|
| 改现有英雄的**玩法数据** | 同 id `.data_champion`（[SOP 05](05-改版现有英雄.md)），保 id 稳定 |
| 现有英雄需要 **Rust 运行时逻辑** | 原生 `replace_champion` / stable `add_champion` 同 id（SOP 05 / 08） |
| 替换/合并**资产文件**（文本、精灵、UI 布局等） | **本 SOP**：`mod.override_info` |
| 加自己的新资产 | 不需要任何规则——放进 mod 文件夹按 `asset/<mod_id>/...` 引用即可 |

`mod.override_info` 能改变英雄**长什么样、显示什么文本**，但不等于注册玩法改版。

## 2. `mod.override_info` 格式

放在 mod 根目录。对象键 = 要改的基础资产路径；`remapping` = 你的替换/补丁资产：

```json
{
  "asset/base/text/ui": {
    "remapping": "asset/example/text/ui",
    "type": "merge"
  },
  "asset/base/aseprite_resources/champions/example_ghoul": {
    "remapping": "asset/example/aseprite_resources/champions/ghoul_king",
    "type": "override"
  }
}
```

| `type` | 语义 | 适用 |
|---|---|---|
| `merge` | **合并 JSON 对象** | i18n 与小型 JSON 增补（首选） |
| `override` | 用你的资产**整体替换**目标路径 | 确要整份替换时 |

⚠️ 该文件含非法 JSON 时，游戏**直接禁用 mod** 并在诊断弹窗报错。

## 3. 操作步骤

1. 在 [SOP 00] 解包的 `base_unpacked` 中找到目标资产，
   确认其打包内路径（如 `asset/base/text/ui` ↔ `base_unpacked/text/ui.i18n`）。
2. 在你的 mod 内准备好对应资产（例如 `mods/example/text/ui.i18n`）。
   merge 时只需包含**要新增/修改的键**，不必复制整份基础文件。
3. 在 `mods/example/mod.override_info` 写规则（merge 或 override）。
4. 重启游戏，进入对应界面验证效果。
5. 不生效 → 标题画面诊断弹窗 → [SOP 10](10-测试与故障排查.md)。

## 4. 典型用例

### 4.1 合并英雄文本（新英雄必需，详见 [SOP 03](03-文本与i18n.md)）

```json
{
  "asset/base/text/champion": {
    "remapping": "asset/my_mod/text/champion",
    "type": "merge"
  }
}
```

### 4.2 替换某个基础精灵

```json
{
  "asset/base/aseprite_resources/champions/example_ghoul": {
    "remapping": "asset/example/aseprite_resources/champions/ghoul_king",
    "type": "override"
  }
}
```

注意路径不带扩展名、不带 `#sheet` 等成员后缀（SOP 04）。

### 4.3 修改游戏设置 JSON

大型 JSON（游戏设置等）同样可以 merge 少量键，而不是整份替换。

## 5. 兼容性守则

- **文本和 JSON 一律优先 `merge`**；`override` 仅在确实要整份替换时用。
- 不要为小改动整体替换全屏 UI 布局——加一个按钮/弹窗用原生扩展
  （[SOP 08](08-原生Stable-Mod开发.md) 的 UI 能力）通常更易保持兼容。
- 多个 mod 编辑同一个键时，最终结果受启用顺序影响；尽量加新键，少动公共键。
- 改版英雄的玩家可见文本走 i18n merge（`asset/base/text/champion`），
  不要把展示文本硬编码进英雄 JSON 或原生代码（SOP 05 §2.4）。
