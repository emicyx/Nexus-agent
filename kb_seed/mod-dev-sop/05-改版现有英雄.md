# SOP 05 · 改版现有英雄（Rework）

> 目标：替换某个基础游戏英雄的玩法数据/运行时逻辑，同时保持其 id、存档、ban/pick
> 引用、补丁数据完全稳定。
> 前置：SOP 02（数据路线）或 SOP 08（原生路线）。
> 源文档：[override-existing-champions](../TeamfightManager2Mod/docs/override-existing-champions.md)

---

## 1. 机制：同 id 即替换

改版的全部机制就是 **id 相同**：内容使用某个基础英雄的精确 id，游戏就用你的版本顶替它。

因为没有单独的「覆盖开关」，也没有 `mod.override_info` 条目：

- 存档、ban/pick 记录（含候选位次）、英雄池、内部花名册顺序、补丁数据继续指向同一英雄；
- 改版**非破坏性**：基础定义不动，你的版本只在 mod 启用时叠在其上；
- **禁用 mod 即还原**为基础英雄；
- 对已有存档也生效（启用即应用）。

两条实现路线（与两类英雄内容对应）：

| 路线 | 做法 | 适用 |
|---|---|---|
| **数据改版**（先试这个） | `.data_champion` 的 `id` = 基础英雄 id | 无需 SDK；接入自动平衡系统 |
| 原生改版 | 注册 `ModChampionInfo` / `StableChampion`，`id()` 返回基础英雄 id | 需要 JSON 表达不了的运行时逻辑 |

## 2. 数据改版流程

### 2.1 找到英雄 id

英雄 id 是游戏英雄数据（`ChampionInfoSheet`）里定义的键——**权威是数据表，
不是精灵/aseprite 路径**（那些只是恰好按英雄命名）。

- 数据 mod：到 `base_unpacked`（SOP 00 解包）的英雄数据里查 id。
- 原生 mod 可直接读表（始终反映当前花名册）：

```rust
for id in db.champion_info_sheet.get_champions_list().keys() { println!("{id}"); }
let exists = db.champion_info("fighter").is_some();
```

### 2.2 写改版文件

```text
mods/my_mod/champion/fighter.data_champion
```

```json
{
  "id": "fighter",
  "category": "Range",
  "tags": ["AD", "Range"],
  "stat":  { "attack": 300, "magic_power": 0, "hp": 3000, "defence": 80,
             "magic_resistance": 50, "move_speed": 1250, "hp_regen": 5,
             "stack": 0, "crit_chance": 0 },
  "growth": { "attack": 15, "magic_power": 0, "hp": 150, "defence": 6,
              "magic_resistance": 4, "move_speed": 14, "hp_regen": 1,
              "stack": 0, "crit_chance": 0 },
  "attack": { "action_name": "attack" },
  "skill":  { "action_name": "skill",  "description": "#asset/my_mod/text/champion?rework_fighter.skill" },
  "skill2": { "action_name": "skill2", "description": "#asset/my_mod/text/champion?rework_fighter.skill2" },
  "ult":    { "action_name": "ult",    "description": "#asset/my_mod/text/champion?rework_fighter.ult" }
}
```

**文件内的一切都会替换原版**：数值、成长、类别、标签、动作、精灵、图标、描述。
schema 与新英雄完全一致（SOP 02）；唯一的区别就是 `id` 用了基础英雄 id（**不要加前缀**）。

### 2.3 保留原版外观（常用）

- **省略 `sprite`** → 保留原基础精灵与动画（只改数值/技能时的正确做法）。
- 同理省略 `skill_icons` / `skill_icon` → 不自定义图标（回退基础图标行为）。
- 只有想连视觉一起换时才设 `sprite`（可配合 [SOP 06](06-资产覆盖与合并.md) 换贴图）。

### 2.4 描述与名字

- 技能描述指向**你自己的命名空间**：`#asset/my_mod/text/champion?rework_fighter.skill`，
  随 mod 附带 `text/champion.i18n`。**不需要** `mod.override_info` merge
  （你引用的是自己的资产路径，不是改基础文本）。
- 只有要改英雄**名字**等以英雄 id 为键的基础文本时，才 merge 进
  `asset/base/text/champion`（[SOP 03](03-文本与i18n.md)）——
  否则玩法数据变了、游戏里仍显示旧名字。

### 2.5 自动平衡

数据改版的动作数字是真实数据字段，**接入自动平衡/补丁系统**
（可补丁字段见 [Patchable Fields](../TeamfightManager2Mod/docs/data-champion-schema/patchable-fields.md)）。
被平衡系统/数据库编辑过的数值在存读档后保留；重载 mod 只重绑行为，不覆盖这些值。

## 3. 原生改版流程

需要自定义运行时逻辑（JSON 表达不了）时：

```rust
// classic API：注册时表达「这是改版」
fn init(_ctx: &GameCtx) -> ModRegistration {
    let mut reg = ModRegistration::new("my_mod");
    reg.replace_champion(MyFighterRework);
    reg
}

impl ModChampionInfo for MyFighterRework {
    fn id(&self) -> &str { "fighter" }   // 基础英雄 id
    // ...stats, actions, passive, etc.
}
```

- `replace_champion` 语义等同 `add_champion`，只是表达意图；
  id 不存在于基础游戏时表现为新增英雄。
- **Stable API 上没有单独的 replace 调用**：`add_champion` 用现有基础英雄 id
  即同样完成改版（见 [SOP 08](08-原生Stable-Mod开发.md)）。

**权衡**：原生动作数字编译在代码里，**不暴露**给自动平衡系统。
想被自动平衡调数 → 用数据改版。

## 4. 优先级与兼容性规则

| 规则 | 说明 |
|---|---|
| 原生 > 数据 | 同一 id 同时有原生与数据注册时，原生机制胜出 |
| 一个 id 一个改版 | 两个启用的 mod 改同一英雄只有一个生效，且受加载顺序影响——视为冲突 |
| 已有存档 | 启用改版即应用于旧存档；禁用即还原 |
| 已编辑/补丁值保留 | 平衡补丁或数据库编辑过的数值在存读档后保留；重载 mod 重绑行为不覆盖数值 |
| 多人联机 | 主机的英雄表权威并同步到客户端；原生运行时行为在每个启用相同 mod 的客户端重绑 |
| `base` 依赖 | 依赖同 id JSON 改版或 `replace_champion` 支持的，要求如 `">=0.4.14"`（SOP 01） |

## 5. 验证步骤（官方四步）

1. 启用 mod，开始/读取一局游戏。
2. 英雄信息界面打开该英雄：数值与技能 tooltip 显示改版值，**id 与名字不变**。
3. 在比赛中选它，确认新行为。
4. 禁用 mod，确认英雄回到基础形态。

## 6. 排错速查（详见 [SOP 10](10-测试与故障排查.md)）

| 症状 | 排查 |
|---|---|
| 改版不生效 | `.data_champion` / `ModChampionInfo::id()` 与基础英雄 id 不完全一致；没重启游戏；mod 有诊断错误 |
| 原生改版不生效 | DLL 用的不是当前 SDK；未用 `replace_champion`（classic）；stable 上 `add_champion` 的 id 写错 |
| 名字/描述还是旧的 | 文本没 merge 进 `asset/base/text/champion` |
| 同 id 冲突 | 另一个 mod 也在改这个英雄；原生与数据同 id 时原生优先 |
| 联机不一致 | 每个玩家都要启用相同 mod；原生 DLL 需 SDK 兼容 |
