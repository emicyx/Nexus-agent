# SOP 11 · 创意工坊发布与更新

> 目标：用游戏自带的 `TFM2ModUploader.exe` 把 mod / 数据库包发布到 Steam Workshop，
> 并持续更新同一物品。
> 前置：SOP 10 验证通过。
> 源文档：[workshop-upload](../TeamfightManager2Mod/docs/workshop-upload.md) ·
> [mod-package](../TeamfightManager2Mod/docs/mod-package.md)

---

## 1. 上传前检查

- [ ] Steam 已运行，并登录到**应持有该 Workshop 物品的账号**
- [ ] mod 文件夹完整（`mod.mod_info` 必需；内容文件齐全）
- [ ] 准备图片：
  - `thumbnail.png`——Mods 菜单缩略图、Workshop 预览后备（也接受 `.jpg`）
  - `preview.png`（推荐，Workshop 专属预览；也接受 `.jpg`）
- [ ] `mod.mod_info` 的 `name/author/version/description` 就绪（上传器直接展示这些）
- [ ] （数据库包）文件夹用 `database_pack.info`，`.tfm2db` 文件直接放包根目录
- [ ] 首次上传前接受 Steam Workshop 法律协议（如 Steam 要求）：
  <https://steamcommunity.com/sharedfiles/workshoplegalagreement>

> 上传器必须放在游戏文件夹内运行（依赖同目录的 Steam DLL 与游戏 app）。

## 2. 发布新物品

1. 运行游戏文件夹中的 `TFM2ModUploader.exe`。
2. **Browse** 选择 mod 或数据库包文件夹。
3. 核对：包类型（Mod / Database Pack）、名称、文件夹 id、作者、版本、预览图、状态。
4. 选择可见性：
   - **Public** 公开 · **Friends only** 好友可见 · **Private** 仅自己 · **Unlisted** 有链接可访问但不列出
5. 写简短 change note（如 `Initial upload`）。
6. 点击 **Publish to Steam Workshop**。

首次上传成功后，上传器在你的包文件夹里生成 id 文件：

```text
my_mod/mod.workshop_id                    ← 普通 mod
my_database_pack/database_pack.workshop_id ← 数据库包
```

**保留它**——这是上传器下次更新同一 Workshop 物品的凭据（内容形如
`{"published_file_id": 3725617184}`）。

## 3. 更新已有物品

1. 确认包文件夹仍在（含 id 文件）。
2. 更新 `version` 字段；准备好新 change note。
3. 打开上传器 → 选同一文件夹 → 写 change note → **Update Workshop Item**。

守则：

- **不要删 id 文件**（除非刻意想发布成新物品）。丢失时从 Workshop 页面 URL 找回
  item id，手工重建该文件。
- 一个本地包文件夹 = 一个 Workshop 物品的唯一事实源；保留备份或源码仓库。
- 发布模板给他人复制时**不含** id 文件——否则别人的上传会尝试更新你的物品。

## 4. 上传内容规则（会传什么/不会传什么）

上传器准备一份临时副本上传。

**普通 mod 包含**：`mod.mod_info`、`mod.override_info`、编译好的原生模块
（`.dll`/`.so`/`.dylib`——放了哪个平台的就传哪个，一个物品服务全平台玩家）、
JSON 与数据文件、PNG/JPG、Aseprite 文件、手动精灵表文件、UI 布局、文本/i18n、
缩略图与预览图。

**普通 mod 跳过**：`src/`、`target/`、`Cargo.toml`、`Cargo.lock`、
`mod.workshop_id`、`database_pack.workshop_id`。
→ 原生源码与构建产物**不上传**，只上传编译模块。

**数据库包包含**：`database_pack.info` + 文件夹内常规文件（`.tfm2db`、预览图）；
跳过两个 workshop id 文件。

代码类 mod 的 Workshop 描述会自动获得 `Runs on:` 行，列出所附二进制覆盖的平台
——由实际文件推导，永远与真实一致。

## 5. 数据库包（Database Pack）

与游戏内 mod 相区分：**Workshop 分发/共享用**，下载后不会自动作为游戏内 mod 启用。

```text
mods/my_database_pack/
  database_pack.info          ← 与 mod.mod_info 同样的基础字段
  league_2026.tfm2db
  fantasy_rosters.tfm2db
  preview.png
```

- 文件夹名 = 包 id；数据库文件**直接**放包根目录（不要自加必需的内层文件夹，
  除非你自己的下载后导入流程确实需要）。
- 上传器检测到 `database_pack.info` 即按 **Database Pack** 类型处理，
  首次上传生成 `database_pack.workshop_id`。

```json
{
  "name": "2026 League Database Pack",
  "author": "Your Name",
  "version": "1.0.0",
  "description": "Custom databases for the 2026 league setup."
}
```

## 6. 原生 Rust mod 的构建上传

**多数 mod 不需要 SDK**——JSON、图片、Aseprite、文本、UI、数据英雄直接上传即可。

上传器按以下规则判定「代码 mod」：所选文件夹含 `Cargo.toml` **或** `src/lib.rs`。
勾选 **Build native Rust code before uploading** 时会在上传前构建 DLL。

### 6.1 Stable mod（推荐路径）

- 判定：`Cargo.toml` 依赖 `mod-api-stable`。
- 上传器用你的默认工具链构建、正确命名产物；`mod-api-stable` 缺失时自动安装
  （查上传器旁 `mod-sdk-stable/`，或 `TFM2_STABLE_SDK_DIR` 环境变量指向的位置）。
- 只为你**运行上传器的平台**构建（Win 上跑 → `my_mod.dll`）；其他平台的二进制
  在各自平台构建后放进文件夹一并上传（SOP 08 §8）。

### 6.2 Classic mod（已弃用，仅维护存量时）

- 需要：匹配的 Mod SDK（放在上传器旁边）+ 可用的 `cargo`/`rustc`
  + （外部 crate 时）网络或 Cargo 缓存。推荐布局：

```text
TeamfightManager2.exe
TFM2ModUploader.exe
steam_api64.dll
bundle.game_data
mod-sdk/
  deps/  native/  build_mod.bat  build_mod_cargo.ps1  rust-toolchain.toml
```

- `Cargo.toml` 存在 → Cargo release 构建，注入 SDK 预构建 `mod_api`，支持常规来源的外部 crate；
  仅 `src/lib.rs` → 旧式直接 `rustc` 构建（只有 `mod_api` 与 `std`）。
- **不要**把 `mod-api` 加进 `[dependencies]`——上传器自动注入匹配的 SDK 构建。
- SDK 应匹配目标游戏版本；游戏更新发布新 SDK 后重编原生 mod。

### 6.3 已自行构建好的 DLL

取消勾选构建选项，直接上传文件夹内现成的 DLL。

## 7. 物品管理习惯（官方建议）

- 首次上传后在**工作副本**里保留 workshop id 文件。
- 发布时更新 `mod.mod_info` / `database_pack.info` 的 `version`。
- change note 写清楚改了什么，订阅者看得懂。
- 发布更新前先本地测试。
- 包文件夹保留备份或源码仓库。
- 模板分享不带 id 文件（见第 3 节）。

## 8. 发布后

- 订阅者侧验证：全新下载 → 启用 → 无诊断。
- 游戏版本更新后的维护 → [SOP 12](12-维护与版本迁移.md)。
