# SOP 02 · 数据英雄（.data_champion）制作

> 目标：用纯 JSON 添加一个可玩英雄（或为改版打基础），不需要 SDK、不需要写代码。
> 前置：SOP 01（骨架已建立）。
> 源文档：[data-champion](../TeamfightManager2Mod/docs/data-champion.md) ·
> [data-champion-schema](../TeamfightManager2Mod/docs/data-champion-schema/index.md)
> （字段全集见 schema，本文是流程与要点）

---

## 1. 文件放置与资产路径

放在 mod 内任意位置，惯例是 `champion/` 子目录：

```text
mods/my_mod/champion/fire_mage.data_champion
```

游戏识别的资产路径（去扩展名）：

```text
asset/my_mod/champion/fire_mage
```

文件是 JSON，但扩展名必须是 `.data_champion`。

## 2. 最小可用结构

`attack`、`skill`、`skill2` 由加载器**强制要求**；`ult` 可选：

```json
{
  "id": "my_mod_fire_mage",
  "category": "Magician",
  "tags": ["AP", "Range"],
  "stat": {
    "attack": 40, "magic_power": 65, "hp": 620,
    "defence": 20, "magic_resistance": 30, "move_speed": 1050,
    "hp_regen": 2, "stack": 0, "crit_chance": 0
  },
  "growth": {
    "attack": 3, "magic_power": 7, "hp": 75,
    "defence": 3, "magic_resistance": 3, "move_speed": 0,
    "hp_regen": 1, "stack": 0, "crit_chance": 0
  },
  "attack": { "action_name": "attack" },
  "skill":  { "action_name": "skill" },
  "skill2": { "action_name": "skill2" },
  "ult":    { "action_name": "ult" }
}
```

- `stat`：1 级基础属性；`growth`：每级成长。九个字段全部显式写出
  （Rust 默认值非零，省略会得到不可预期的数）。
- `crit_chance` 是 0–100 的百分数。
- **数值量级**：参考基础英雄（`move_speed` 约 900+、普攻 `range` 约 60000、
  近战约 12000）。用 SOP 00 解包的 `base_unpacked` 对照，不要凭空写。

## 3. 标准开发顺序（官方推荐）

1. **先复用基础游戏精灵**：`sprite` 直接指向 `asset/base/...` 的现有资源，或不设 sprite。
2. 启动游戏确认英雄出现在游戏内（见第 7 节验证）。
3. 之后再补自己的图标、文本、动画（SOP 03 / 04）。
4. 数值与技能效果在这一步反复调整。

这样能先把「数据对不对」和「美术对不对」两类问题分开排查。

## 4. 动作（Action）字段

四个动作槽：`attack` / `skill` / `skill2` / `ult`，每个是一个 `DataActionDef`：

| 字段 | 说明 | 默认 | 注意 |
|---|---|---|---|
| `action_name` | 动画标签，同时是补丁类型名 | — | 惯例与槽位同名；**发布后不要改**（影响补丁/平衡引用与动画查找） |
| `duration` | 动作总时长（tick） | 0 | 60 tick = 1 秒 |
| `cooltime` | 冷却（tick） | 0 | `240` = 4 秒 |
| `start_timing` | 动作内效果触发的 tick | 0 | |
| `cancelable` | 可否被打断 | false | |
| `range` | 基础施法距离 | 0 | 世界单位，见量级说明 |
| `growth_range` | 每级额外距离 | 0 | |
| `casting_type` | `Targeting` / `Position` / `Direction` / `None` | `Targeting` | `None` 无需目标输入（自 buff / 自身周围 AOE 常用） |
| `casting_target` | AI 如何选目标 | **`Ally`** | ⚠️ 默认值对进攻内容几乎总是错的，**必须显式写** |
| `attack_type` | `BaseAttack` / `Skill` / `Dot` / `DotIgnoreShield` / `Item` / `Well` | `BaseAttack` | `attack` 槽用 `BaseAttack`，技能槽用 `Skill` |
| `can_use_with_move` | 移动中可施放 | false | |
| `effect` | 效果定义（`DataEffectDef`） | null | 在 `start_timing` 触发 |
| `description` | 纯文本或 i18n 键 | — | i18n 键格式见第 6 节 |

常用 `casting_target`：`Enemy`、`EnemyWithoutTower`、`EnemyChampion`、`EnemyChampionInCC`、
`Ally`、`AllyChampion`、`AllyNotSelf`、`AllyOnlySelf`、`Both`、`BothChampion`、`None`。

## 5. 效果（Effect）速览

效果用**内部标签**编码：对象带 `"type"` 字段。分组：

| 分组 | 效果类型 |
|---|---|
| 伤害/治疗 | `Attack`、`ApAttack`、`FixedAttack`、`Heal`、`Shield` |
| 控制 | `Stun`、`Airborne`、`Knockback`、`Grab`、`Pull`、`Fear`、`Charm`、`Bind`、`Taunt`、`BlockAttack`、`BlockSkill`、`BlockMoveSkill`、`Invisible`、`Banish` |
| 位移 | `Rush`、`RushTime`、`Teleport`、`DirTeleport`、`MoveBack`、`MoveTo`、`MoveToTarget`、`RushMoveToBack` |
| 投射物 | `LinearProjectile`、`TargetProjectile`、`TargetSplashProjectile`、`AutoTargetProjectile`、`RangeProjectile`、`ParabolicProjectile`、`BackToCasterLinearProjectile`、`TargetProjectileFromProjectile`、`LineRangeProjectile`、`RangePeriodProjectile`、`ApplyInProjectile` |
| 范围/屏障 | `RangeEffect`、`ShrinkingBarrier` |
| Buff | `AddBuff`、`AddCasterBuff`、`RemoveCasterBuff`、`AddCasted` |
| 组合/分支 | `Combine`、`Delayed`、`WithSelf`、`RandomTarget`、`SwitchByBuff`、`SwitchByLevel3` |
| 视听触发 | `ViewEffect`、`CasterViewEffect`、`CasterAnimation`、`RemoveCasterAnimation`、`Sfx`、`TargetSfx` |

**每个效果的完整字段与默认值查
[Effect Schema](../TeamfightManager2Mod/docs/data-champion-schema/effects.md)，
常用组合直接抄
[Recipes](../TeamfightManager2Mod/docs/data-champion-schema/recipes.md)。**

### 必须记住的效果规则

1. **所有时间字段是 tick**（60/s），不是毫秒。
2. `applied_effects` 里是**包装对象**，不是裸效果：
   ```json
   "applied_effects": [
     { "effect": { "type": "Attack", "damage": 50 }, "casting_type": "Targeting" }
   ]
   ```
3. 效果内部的目标选择默认值同样来自 Rust 且常为 `Ally`
   （如 `LinearProjectile.applied_target`、`RangeEffect.target`）——伤害/敌方效果**必须显式指定**。
4. CC 效果的时长字段名不统一：`Stun/Airborne/Bind/Taunt/Banish` 用 `duration`；
   `Knockback/Grab/Pull/Fear/Charm/Block*/Invisible` 用 `tick`。照 schema 抄，别猜。
5. `shape` 是外部标签枚举：`{ "Circle": { "radius": 8000 } }`、
   `{ "Rect": { "width": 12000, "height": 8000 } }`、
   `{ "DirDot": { "radius": 8000, "range": 700 } }`。
6. `RangePeriodProjectile.period`、`AddCasted.period` 最小被钳制为 1，自己保证 > 0。
7. 视觉触发类（`ViewEffect`/`Sfx` 等）的 `name` 必须在 `view_effects`/`view_projectiles`/`view_buffs`
   中注册同名条目（见 [Visual Bindings](../TeamfightManager2Mod/docs/data-champion-schema/visual-bindings.md)）。

### 完整示例（可直接改造）

官方火法师完整示例（远程 AP 英雄：普攻弹道 + 方向穿透技能 + 自 buff + 范围大招 +
弹道视觉绑定）见
[data-champion.md · Example Champion](../TeamfightManager2Mod/docs/data-champion.md#example-champion)，
此处不重复粘贴。要点：

- 普攻：`TargetProjectile` + `applied_effects` 内 `Attack`（`attack_ratio: 100` 即 100% AD）。
- 方向技能：`LinearProjectile`（`penetrate: true`）+ `ApAttack`。
- 自 buff：`casting_type: "None"` + `casting_target: "AllyOnlySelf"` + `AddCasterBuff`。
- 大招：`RangeEffect`（`apply_type: "AroundCaster"`）+ `Combine` 组合伤害与 `Stun`。
- 弹道视觉：`view_projectiles` 数组按 `name` 与效果内的 `name` 精确匹配。

## 6. 文本（描述）

技能描述通常指向 i18n 键：

```json
"description": "#asset/my_mod/text/champion?description.my_mod_fire_mage.skill"
```

键的内容通过 i18n 合并提供（[SOP 03](03-文本与i18n.md)）。
新英雄**必须**合并进 `asset/base/text/champion`，否则英雄列表、ban/pick、tooltip 读不到名字。

## 7. 视觉绑定（sprite / 图标）——开发期先从简

| 场景 | 写法 | 说明 |
|---|---|---|
| 测试期：静态 PNG | `"sprite": "asset/my_mod/champions/fire_mage_idle"`（**不设** `anim_prefix`） | 整图作为单帧，自动生成 `idle/attack/skill/skill2/ult/dead/run` 兜底动画 |
| 测试期：复用基础精灵 | `"sprite": "asset/base/aseprite_resources/champions/pyromancer"` | 按需配 `anim_prefix` |
| 正式：Aseprite / 手动动画表 | `"sprite": "asset/my_mod/champions/fire_mage"` + `"anim_prefix": ""` | 详见 [SOP 04](04-图标与精灵图.md) |

技能图标两种写法：

```json
"skill_icons": [ "asset/my_mod/icons/fire_skill", "asset/my_mod/icons/fire_skill2", "asset/my_mod/icons/fire_ult" ]
```

```json
"skill_icon": { "source": "asset/my_mod/icons/fire_skills", "tags": ["fire_skill", "fire_skill2", "fire_ult"] }
```

（索引 0 = skill，1 = skill2，2 = ult；`skill_icons` 优先于 `skill_icon`。）

## 8. 自动平衡（Patchable Fields）

数据英雄的动作数字是真实数据字段，接入游戏的自动平衡/补丁系统。
每个动作暴露 `cooltime`、`range`、`duration`、`start_timing`，
以及效果的部分字段（如 `Attack.damage`、`Stun.duration`、`LinearProjectile.speed`）。
全集见
[Patchable Fields](../TeamfightManager2Mod/docs/data-champion-schema/patchable-fields.md)。
这也是「能不用原生就不用原生」的实际理由之一：原生动作数字编译进代码，补丁系统够不着。

## 9. 验证

1. 重启游戏，Mods 菜单启用 mod，再次重启。
2. 进入游戏：英雄出现在可选池 / 冠军信息界面。
3. 打一场比赛：普攻、两个技能、（如有）大招行为正确。
4. 检查 tooltip 文本、图标显示。
5. 任何异常先看标题画面诊断弹窗 → [SOP 10](10-测试与故障排查.md)。

## 10. 常见错误

| 症状 | 排查 |
|---|---|
| 英雄不存在 | 扩展名不是 `.data_champion`；缺 `attack`/`skill`/`skill2`；JSON 非法；id 与其他 mod 撞 |
| 技能打不到人 / 打队友 | `casting_target` 或效果的 `applied_target`/`target` 漏写（默认 `Ally`） |
| 数值离谱 | 单位记错（tick vs 秒）；量级没对照基础英雄 |
| 枚举报错 | 枚举值必须精确拼写（区分大小写），如 `Targeting`、`Enemy`、`BaseAttack` |
| 描述为空 | description 键没合并进 `asset/base/text/champion`（SOP 03） |
| 动画不动 | 动画源缺对应 tag；`anim_prefix` 缺失或前缀对不上（SOP 04 / SOP 10） |
| 改版不生效 | id 必须与基础英雄**完全一致**（SOP 05） |
